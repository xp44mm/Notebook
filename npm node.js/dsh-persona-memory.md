`dsh-persona-memory` 插件旨在让 AI 助手实现“跨会话”的持久记忆。它的核心交互方式可以归纳为以下几种：

### 🧠 手动记忆管理：通过对话直接操作

这是最直观的方式，你可以在聊天中直接告诉 AI 去“记住”什么。

*   **核心工具 `memory`**：AI 会调用此工具来执行具体的记忆操作。
    *   `add`：添加新记忆。
    *   `read`：读取记忆。
    *   `update` / `delete` / `rewrite`：更新、删除或重写记忆。
    *   `which`：选择操作哪种记忆，如 `memory`（通用）、`user`（用户画像）或 `failure`（失败教训）。
    *   `project`：为特定项目（基于 Git 仓库）操作独立的记忆。

> 例如，你可以对 AI 说：“记住，我讨厌用 `sudo` 命令。”AI 就会调用 `memory add` 来保存这条信息。

### 📌 常驻指令管理：通过 `/standing` 命令

这类指令用于设定你希望 AI **始终遵守**的规则，具有最高优先级。

*   **列出指令**：`/standing`
*   **添加指令**：`/standing add <你的指令文本>`
*   **移除指令**：`/standing remove <编号>`（编号通过 `/standing` 命令查看）
*   **清空指令**：`/standing clear`

> **注意**：`/standing` 指令是**用户专属**的，AI 模型无法通过对话来修改它，这能有效防止模型“偷偷”写入不期望的规则。

### 🤖 自动学习机制：让记忆“自己长出来”

插件内置了自动化功能，能主动从对话中学习，减少手动操作。

*   **后台学习**：每隔一定轮次的对话（默认10轮），系统会自动复习并提取新的事实存入记忆。
*   **纠正检测**：当你用 `/feedback` 或对话中表达纠正、不满时，插件会将其记录为 `[correction]` 失败条目，避免再犯。
*   **失败记忆**：会专门记录失败的经历和教训（`failures.md`），并自动注入到上下文中，防止重蹈覆辙。
*   **自动合并**：当记忆超限时，系统会自动进行精简和合并，优先保留重要信息。

### 🖥️ WebUI 管理：可视化操作

除了对话，你还可以在 DSH 的 Web 设置页面进行可视化管理。

*   **记忆管理区块**：在设置页的「记忆管理」区域，可以增删改常驻指令、编辑三个核心记忆文件（`MEMORY.md`, `USER.md`, `failures.md`）的条目、浏览和编辑项目记忆。
*   **索引管理**：查看和重建 FTS5 全文索引与向量索引的状态。
*   **配置与备份**：调整 40 多项插件配置，并进行本地备份与恢复。

### 🔍 检索与查看：高效查找记忆

*   **`memory_search` 工具**：支持混合检索，优先使用 **FTS5 全文索引**和**语义向量**进行搜索，即使数据库不可用也能回退到子串扫描。
*   **用量提示**：每次 `memory` 操作都会返回当前的记忆用量百分比，当达到 90% 时会提醒你进行合并或清理。

### 🛡️ 安全与约束

*   **内容扫描**：每次写入记忆时，系统会自动扫描并拦截 API Key、私钥等敏感信息，防止它们被意外记录。

总结来说，`dsh-persona-memory` 的操作方式很灵活：日常对话中让 AI 自动学习，重要规则用 `/standing` 固定，需要精细管理时则通过 WebUI 完成。
